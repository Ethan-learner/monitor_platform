## 1. 平台简介

统一监控告警平台是面向运维和开发人员的**一站式告警管理中心**，集中管理：

- **告警规则** — PromQL 表达式定义什么情况触发告警
- **通知策略** — 告警触发后通过什么渠道（邮件/飞书/电话）通知谁
- **静默规则** — 在指定时间段内屏蔽特定告警
- **抓取配置** — 管理 Prometheus 采集哪些目标
- **告警记录** — 历史告警的查询和追溯

> 平台地址：https://172.16.10.99 （内网访问）

### 2.1 登录

1. 在浏览器打开平台地址
2. 输入 **公司域控账号和密码**（与公司邮箱/办公系统密码一致）

点击页面右上角用户头像 → 「退出登录」

### 2.3 角色说明

| 角色 | 说明 |
|------|------|

## 3. 告警中心

### 3.1 查看活跃告警

**路径**：左侧导航 → 告警中心 → 活跃告警

页面展示当前正在触发的所有告警，按分类（服务器/数据库/应用等）展示。

**每行信息**：
- 告警名称 — 如 `InstanceDown`、`HighCPUUsage`
- 级别 — 严重(critical) / 警告(warning) / 信息(info)
- 实例 — 触发告警的机器或服务
- 分类 — 所属大类
- 已持续 — 告警持续时长

> 告警数据实时从 Prometheus API 拉取，刷新页面或点击「刷新」按钮可获取最新状态。

### 3.2 管理告警规则

**路径**：左侧导航 → 告警中心 → 规则管理

管理所有 Prometheus 告警规则，支持**创建、编辑、禁用、删除**操作。

#### 3.2.1 查看规则列表

规则按分类分组展示（服务器告警 / 数据库告警 / 平台组件告警 / 应用告警 / 性能告警），每组显示该分类下的规则数量。

点击规则左侧箭头可展开查看详情（表达式、持续时间、描述）。

**状态标签含义**：

| 标签 | 含义 |
|------|------|
| 🟢 启用 | 规则已生效，正常评估中 |
| 🟠 禁用 | 规则已暂停，不参与评估 |
| 🔵 待生效 | 规则已创建但尚在冷却期，15 分钟后自动生效 |
| 🔴 已删除 | 规则已移除（不显示在列表中） |

#### 3.2.2 创建规则

1. 点击右上角「创建规则」按钮
2. 填写以下信息：

   | 字段 | 说明 | 示例 |
   |------|------|------|
   | 分类 | 规则所属大类 | 服务器告警 |
   | 告警名称 | 唯一标识，不能重复 | HighCPUUsage |
   | 表达式 | PromQL 查询语句 | `cpu_usage > 90` |
   | 持续时间 | 满足条件多久后触发 | `5m`（5分钟） |
   | 通知策略 | 选哪个策略模板（或自定义） | — |
   | 自定义接收人 | 不选策略时，直接填通知对象 | `critical:email:zhulei1@longcheer.com` |
   | 描述 | 告警说明 | 服务器 CPU 使用率过高 |

3. 填写表达式后，可点击「预览」查看当前匹配多少条时间序列
4. 点击「创建」提交

#### 3.2.3 告警风暴防护

创建规则时，系统会自动检查：

- **表达式是否包含标签过滤**（即 `{}` 条件）
- **匹配的时间序列数量**

如果匹配条数 > 0 或缺少标签过滤，系统会弹出 **告警风暴提醒** 确认框：

```
当前匹配条数：284
确认要继续创建吗？
```

- 点击 **确认创建** → 规则以 **待生效** 状态写入，**15 分钟后自动生效**，期间不会触发告警
- 点击 **取消** → 放弃创建

> 匹配条数越多，潜在告警量越大，请谨慎确认。

#### 3.2.4 编辑规则

点击规则行右侧的 ✏️ 编辑图标，修改规则信息后保存。

#### 3.2.5 禁用/启用规则

点击规则行右侧的 🛑 禁用图标。

- **禁用**：规则暂停评估，YAML 文件移入 `alerts_disabled/` 目录
- **启用**：恢复评估，YAML 文件移回 `alerts/` 目录

#### 3.2.6 删除规则

点击规则行右侧的 🗑️ 删除图标并确认。

- 规则标记为已删除（状态 -1）
- YAML 文件移入 `alerts_deleted/` 目录（带时间戳，可追溯）

### 3.3 静默告警

**路径**：左侧导航 → 告警中心 → 静默管理

在指定时间段内屏蔽符合条件的告警通知。

#### 3.3.1 创建静默

1. 点击「创建静默」按钮
2. 选择匹配条件（支持多个条件组合）：
   - **标签名**：如 `alertname`、`instance`、`severity`
   - **匹配值**：精确值或正则表达式
3. 设置**开始时间**和**结束时间**
4. 填写备注说明原因
5. 点击提交

> 示例：静默 `InstanceDown` 告警在 2026-07-22 10:00~12:00 期间不发送通知。

#### 3.3.2 过期静默

静默到期后自动失效，也可手动点击「过期」提前终止。

#### 3.3.3 重置静默

对已过期的静默可点击「重置」，修改时间后重新生效。

### 3.4 查看告警历史

**路径**：左侧导航 → 告警中心 → 历史告警

查询已过去的告警记录，支持按告警名称、级别、状态、时间范围等多维度筛选。

- **firing** — 曾经触发的告警
- **resolved** — 已恢复的告警

## 4. 通知策略

**路径**：左侧导航 → 告警中心 → 通知策略

通知策略定义告警触发后**通过什么渠道通知谁**。策略按级别（critical / warning / info）分层配置。

### 4.1 创建通知策略

1. 点击「创建策略」
2. 填写策略名称
3. 配置各级别的通知渠道和接收人：

| 级别 | 说明 | 点击后的配置项 |
|------|------|---------------|
| **严重 (critical)** | 最高级别，需要立即响应 | 邮件 + 飞书 + 电话 |
| **警告 (warning)** | 需要关注但不紧急 | 邮件 + 飞书 |
| **信息 (info)** | 仅记录，无需处理 | 仅邮件 |

4. 每个渠道可填写多个接收人：
   - **邮件**：填写邮箱地址，多个用逗号分隔
   - **飞书**：填写飞书用户 ID，多个用逗号分隔
   - **电话**：填写手机号（预留）
5. 点击保存

> 策略创建后默认启用，可在列表页禁用/启用。

### 4.2 关联规则与策略

创建或编辑规则时，在「通知策略」字段选择已创建的策略模板。

- 选择策略模板后，规则的级别下拉会自动按策略覆盖级别过滤
- 也可选择「自定义」直接填写接收人，不依赖策略模板

### 4.3 策略删除

删除策略时：

- 关联该策略的规则**自动禁用**（避免无通知渠道的规则产生告警）
- 重新创建同名策略后，关联规则**自动恢复启用**

## 5. Webhook 推送

**路径**：左侧导航 → 系统监控 → Webhook

### 5.1 查看推送记录

页面展示告警推送的完整日志，包含：

| 字段 | 说明 |
|------|------|
| 告警名称 | 触发推送的告警 |
| 实例 | 告警来源实例 |
| 通道 | 推送渠道（email / lark） |
| 状态 | 成功 / 失败 |
| 摘要 | 推送内容或错误信息 |
| 操作 | firing(触发) / resolved(恢复) / repeat(重复) |
| 接收人 | 实际推送到谁 |
| 时间 | 推送时间 |

> 如果某通道未配置接收人，状态显示为「未触发」（灰色）。

## 6. 抓取配置管理

**路径**：左侧导航 → 指标采集 → 抓取配置

管理 Prometheus 采集哪些目标（服务），替代手动编辑 YAML 文件。

### 6.1 页面结构

页面分左右两栏：

- **左栏**：文件夹树，按**部门**→**配置文件**层级组织
- **右栏**：选中文件夹或配置文件后，显示对应的 Dashboard 或目标列表

### 6.2 浏览结构

**目录层级**：

```
部门（文件夹）
  └─ 配置文件（如 nginx.yaml、prometheus.yaml）
       └─ 抓取目标（如 172.16.10.27:9100）
```

- 点击**部门文件夹** → 右栏显示该部门总览
- 点击**配置文件** → 右栏显示该文件下的所有目标列表

### 6.3 新增目标

1. 在左栏选择一个配置文件（如 `系统配置 / nginx.yaml`）
2. 右栏点击「新增目标」
3. 填写信息：

   | 字段 | 说明 | 示例 |
   |------|------|------|
   | 目标地址 | 采集目标 IP:端口 | 172.16.10.27:9113 |
   | 标签 | 附加标签（JSON 格式） | `{"service":"nginx"}` |

4. 点击「确定」提交

> 提交后自动同步到服务器 YAML 文件，Prometheus 自动发现新目标（无需重启）。

### 6.4 编辑/禁用/删除目标

- **编辑**：修改目标地址或标签
- **禁用**：暂停采集该目标，文件移入 `_disabled/` 目录
- **删除**：移除目标，文件移入 `_deleted/` 目录（带时间戳）

### 6.5 管理部门和配置文件

- **新建文件夹**：新增一个部门（文件夹）
- **新建配置文件**：在部门下新增一个 `.yaml` 配置文件
- **删除**：移除整个文件夹或配置文件（级联删除下属目标）

### 6.6 采集效果 Dashboard

在左栏选择 **「全部」** 视图，右栏展示整个系统的采集健康状态：

**统计卡片**：
- 生效目标数（🟢）
- 未生效目标数（🟡）
- 失效目标数（🔴）

**图表**：
- 环形图：各配置文件目标分布
- 柱状图：各配置文件健康对比

**未生效列表**：展示所有 Prometheus 未采集到的目标及错误信息。

## 8. 常见问题

### Q1: 创建规则后状态一直显示「待生效」？

等待 15 分钟后会自动生效。这是告警风暴防护机制，防止新建规则立即触发大量告警。

### Q2: 创建规则提示「规则名已存在」？

告警名称在平台内唯一，不能重复。如果确认要重建，先删除旧的同名规则。

### Q3: 为什么收不到告警通知？

请依次检查：
1. 规则是否**已启用**（状态为 🟢）
2. 规则是否关联了**通知策略**
3. 通知策略中该级别是否配置了**接收人**
4. Webhook 服务是否正常（查看系统监控 → Webhook 页面）

### Q4: 新增抓取目标后 Prometheus 没采集到？

`file_sd_configs` 自动发现最长可能有 1-2 分钟延迟。点击「刷新」查看最新状态。如果长时间未生效，检查目标地址是否可达。

### Q5: 如何查看谁在什么时候做了什么操作？

审计日志自动记录所有关键操作（创建/编辑/删除规则、静默、策略变更等），数据存储在 `audit_log` 表中（审计日志查询页面待开发）。

### Q6: 登录提示「账号或密码错误」？

- 确认使用的是公司域控账号
- 域控不可用时，请管理员在用户管理页面创建本地账号
- 忘记密码请联系管理员重置
