# 统一监控告警平台 — 功能介绍演讲稿

> 面向平台使用者的功能介绍会议 · 2026-07

---

## 一、开场（1 分钟）

各位好，今天给大家介绍我们新搭建的**统一监控告警平台**。

一句话说清楚这个平台做什么——**集中管理所有告警的生命周期**：从告警规则怎么定、触发了怎么通知谁、到历史怎么追溯，一平台搞定。

---

## 二、平台定位（2 分钟）

先看看我们之前的告警流程有什么痛点：

| 问题 | 以前 | 现在 |
|------|------|------|
| 规则管理 | 运维登录服务器手写 YAML | 页面点几下就行 |
| 通知渠道 | 通知发到哪、发给谁，不清楚 | 策略模板统一管理 |
| 告警历史 | 触发完就没了，查不到 | MySQL 落库可追溯 |
| 采集配置 | 改个 target 要上服务器 | 页面 CRUD 自动同步 |

简单说就是把**运维工作台搬到了浏览器里**。

---

## 三、核心功能演示（10 分钟）

### 3.1 告警规则管理（3 分钟）

**【操作演示】**

1. 进入 **告警中心 → 规则管理**
2. 页面展示所有规则，按分类分组（服务器/数据库/应用/平台组件/性能）
3. **创建一条规则**：
   - 填写名称、表达式
   - 点击「预览」看当前匹配多少条数据
   - 选择通知策略或自定义接收人
   - 点击创建

**【重点介绍】** 告警风暴防护：

> "创建时系统会自动检查匹配条数。如果匹配数量大，会弹出提示框——当前匹配 XXX 条，确认创建？确认后规则不是立即生效，而是先标记为**待生效**，15 分钟后自动加载。这 15 分钟相当于一个冷却期，防止新规则直接打爆通知通道。"

4. 规则行的 **状态标签**：
   - 🟢 启用 — 正常工作中
   - 🟠 禁用 — 临时关闭
   - 🔵 待生效 — 冷却期内
5. 快捷操作：点击禁用图标暂停规则，点击删除移除规则

### 3.2 通知策略（2 分钟）

**【操作演示】**

1. 进入 **告警中心 → 通知策略**
2. 展示已有策略列表
3. **创建一条策略**：
   - 先看三个级别：严重(critical) / 警告(warning) / 信息(info)
   - 每个级别可以配置多个通道：邮件、飞书、电话
   - 每个通道可以填多个接收人

> "比如线上核心服务挂了，critical 级别同时发邮件+飞书+电话；如果是磁盘快满了但还没满，warning 级别只发邮件。谁值班通知谁，不用每次改。"

4. 策略创建后，在**规则**那边直接勾选就行

### 3.3 静默管理（1 分钟）

**【操作演示】**

1. 进入 **告警中心 → 静默管理**
2. **创建静默**：选标签、填匹配值、设时间段
3. "比如凌晨 2 点要发版，肯定会触发告警，新建一个静默覆盖发版窗口，运维不会半夜收到告警电话"

### 3.4 历史告警（1 分钟）

**【操作演示】**

1. 进入 **告警中心 → 历史告警**
2. 按名称、级别、时间筛选
3. "以前告警触发完就找不到了，现在所有告警都落库，事后复盘可以直接查"

### 3.5 采集配置管理（3 分钟）

**【操作演示】**

1. 进入 **指标采集 → 抓取配置**
2. 左栏是目录树：**部门 → 配置文件 → 目标**
3. 点击配置文件，右栏展示该文件下所有目标
4. **新增目标**：填 IP:端口 + 标签 → 自动同步到服务器
5. 点击「全部」视图，展示**采集健康大盘**：
   - 三个卡片：生效/未生效/失效
   - 环形图：各文件目标数占比
   - 未生效列表：哪些目标 Prometheus 没采集到，什么原因

> "以前改采集目标要 SSH 到服务器上改 YAML，现在在页面点几下就行。Prometheus 会自动发现，不需要重启。"

### 3.6 Webhook 状态查看（30 秒）

1. 进入 **系统监控 → Webhook**
2. 看三个 Webhook 节点是否健康
3. 查推送记录：谁通过什么渠道收到了什么告警

## 四、权限体系（1 分钟）

| 角色 | 范围 |
|------|------|
| ops | 什么都能看、什么都能做 |
| dev | 看告警、看规则、看 APM |
| mgmt | 只看总览和看板 |

> "权限分了三层：菜单权限控制你能看到什么页面，功能权限控制你能不能点某个按钮，管理权限控制你的管理范围（目前预留）。ops 角色自带全部权限。"

## 五、数据流总览（2 分钟）

用一张图说清整个链路：

```
你页面操作
   │
   ▼
API 写入 MySQL（规则、策略、目标等元数据）
   │
   ├─ SSH 同步到 Prometheus 服务器（YAML 文件）
   │    └─ 三节点自动热加载
   │
   ▼
Prometheus 评估 → 触发告警 → Alertmanager 分组去重
   │
   ▼
Webhook 服务（3 节点集群）
   │
   ├─ 查 MySQL 拿通知策略
   ├─ 发邮件 / 飞书
   ├─ 写告警记录到 MySQL
   └─ 写推送日志
```

一句话总结：**你在页面点的每一下，后台走的是 MySQL + SSH + 三节点热加载，最终影响到 Prometheus 的行为**。

## 六、收尾（30 秒）

**平台能帮大家**：
1. 不用再上服务器改配置
2. 告警通知不会漏，也不会炸
3. 历史告警随时查
4. 新增机器/服务，页面配一下就行

大家现在可以访问试试，有问题随时反馈。
